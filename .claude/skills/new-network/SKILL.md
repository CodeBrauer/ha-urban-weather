# New network

A network is visible in many places. Work through every section; a section that does not apply is skipped on purpose, not forgotten. Find the places that list all networks with `rg -n -i 'dortmund' -g '!custom_components/**' -g '!tests/**'` (any existing network works as the search term).

## 1. Preconditions

- A `Network: <City> (<CC>)` issue (template `.github/ISSUE_TEMPLATE/new_network.yml`) whose checklist is complete: 12 points, the same for every network issue and defined in epic #33; the issue list shows the progress ("9 of 12"). Criteria: live values at least hourly, a licence that allows reuse, stations across the city, no login.
- The limits and the planned budget are agreed in that issue before any code ("The network APIs are shared, rate-limited resources" in `AGENTS.md`). Explore the API with a few manual requests only.

## 2. Code

- **Provider:** reuse a provider class when the platform matches. An Opendatasoft dataset is configuration only: an `OpendatasoftDataset` and a `Network` in `providers/<city>.py`, like `providers/dortmund.py`. A new platform gets a provider class (`SensorProvider` or `BulkProvider`, see "Providers" in `docs/en/developer/architecture.md`) and reuses `providers/common.py`.
- **`Network`** (`provider.py`):
  - `id`: stable for good, it is stored in every config entry of the network.
  - `name`, `operator`: device info of the entities.
  - `area`: title of a location without a known district.
  - `endpoint`: its host appears in error messages.
  - `fields`: only the values the network measures; entities follow from them. Units and combination rules: `docs/en/developer/fields.md`; a planned value gets its `Field` member as described there.
  - `attribution`: operator and licence, as in the data sources table.
  - `limits`: `RequestLimits` from the documented limits, planned budget below them.
  - `tiles`: `BASEMAP_DE`, `OSM_CH` or `OPENSTREETMAP`; a new layer goes to `providers/common.py`.
- **Registry:** a factory in `PROVIDERS` (`providers/__init__.py`).
- **Reference data** (siting metadata, LCZ) is optional. If added: generated by a script into `providers/<city>/data/` and listed under "Generated and vendored files" in `AGENTS.md`.
- **UI strings** stay network-neutral: no city names in `strings.json` and `translations/`. The network name comes from `Network.name`.

## 3. Tests

- A trimmed real response in `tests/fixtures/<city>.json`. Its source, date and trim filter go in the loader's docstring in `tests/common.py`, next to the test location constants (`DORTMUND_HOME`, `DORTMUND_NOW`, ...).
- `tests/test_<module>.py` for a new provider module, otherwise extend the existing file.
- Cover parsing and units, grouping sensors into stations, replaced or stale sensors, `requests_per_refresh()`, and the recommendation (without siting data: nearest station only).

## 4. Documentation

`docs/en/` first, then translate the diff to `docs/de/` with the `docs-site` skill.

| Page | Change |
|---|---|
| `index.md` | Intro sentence naming the networks, row in "Supported networks" |
| `networks/<city>.md` | New page from an existing one (overview table, coverage, data, limits, quirks); add it to `nav` in `mkdocs.yml` and `mkdocs.de.yml` and as a row in `networks/index.md` |
| `data-sources.md` | Source and licence row, attribution sentence |
| `user/api-limits.md` | Section for the network: limits, request model, budget |
| `user/installation.md` | API host in the "Internet" requirement |
| `user/stations.md` | Only for a network without siting data or with quirks in station grouping |
| `user/setup.md` | Only for network-specific advice (e.g. dew point correction) |
| `developer/architecture.md` | New provider class, package or tile layer |
| `developer/reference-data.md` | Only with reference data |

Screenshots only change when their motif should show the new network (`scripts/screenshots.py`).

## 5. Repository files

- `README.md` and `README.de.md`: list of supported networks (with station count), data sources and licences.
- `AGENTS.md`: intro, layout table (new provider files), the API section (host and limits), test fixtures.
- `mkdocs.base.yml`: `site_description`.

## 6. Outside the code

Done by the person you work for, or with their approval:

- GitHub repository description ("Supported: …") and a topic with the city name.
- Social preview image (Settings → Social preview): it names the networks and the station count. Keep text inside the area the repository card shows (about y 75–560 of 1280×640).
- Close the network issue with the release.

## 7. Release

A new network is a MINOR bump ("Versioning" in `AGENTS.md`). The release notes name the network and its station count. Runbook: the `release` skill.
